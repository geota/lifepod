# Notes for AI-assisted changes

LifePod is one offline web page in `web/`, wrapped by a Kotlin WebView app (`android/`) and a SwiftUI WKWebView app (`ios/`). There's no build step for the web code. `design/polish/SPEC.md` describes how the board behaves, [docs/GUIDE.md](docs/GUIDE.md) has the rules players see, and [docs/DEVELOPING.md](docs/DEVELOPING.md) covers setup, builds, tests and CI. The README keeps a short feature list.

Run `npm run check` before every commit. It runs ESLint, the compatibility lint, the type check, ktlint, swift-format and every test. There's no commit hook, so nothing else runs them before CI. For Android changes, also run `npm run lint:android` and `./android/build.sh`.

Before asking for review, go through the checklist in [docs/REVIEWING.md](docs/REVIEWING.md).

## Invariants

- **Offline, with no network.** The Android manifest has no `INTERNET` permission, and nothing may load from a URL. Bundle every file, including fonts and icons.
- **The CSP is `default-src 'none'`** (the `<meta>` in `web/index.html`). There are no inline scripts, `style` attributes, `<style>` blocks or `on…` handlers. Styles go in the stylesheets in `web/css/` or are set from script through `element.style`/CSSOM, and scripts are files. Every fetch directive is `'self'`: both apps serve the page from a real origin and the tests over http, so it needs no `file:`. Don't add other sources; `tests/native.test.mjs` checks the whole policy.
- **The floor is iOS 18.0, and Android 11 with WebView 129.** WKWebView on iOS 18 (Safari 18.0) and the Android System WebView as Chrome 129 (the same month, September 2024) are the binding limits; a feature needs both. The WebView updates through Google Play, so the device minimum stays Android 11 (minSdk 30), and `MainActivity.kt` checks the installed WebView at launch: below `MIN_WEBVIEW_MAJOR` it shows a native notice with a button to its Play page instead of the board. Keep `MIN_WEBVIEW_MAJOR` and the browserslist's Chrome entry in step. CI's WebKit is current, so it doesn't catch newer features. `npm run lint:compat` does, through the `browserslist` in `package.json`. Feature-detect anything newer and give it a fallback. Don't raise the floor in passing.
- **Old saves must keep loading.** `loadGame` in `web/js/logic/save.js` validates every field of the saved game and falls back to a default when a field is missing or wrong. Keep that for every new field. When a field's meaning changes, add a version and migrate older saves (see `identitySettingsVersion`). Never make an old save throw or reset the game.
- **Every touch target is at least 44px** (`--tap-min`), at every board size down to the 320 × 568 stress test. Shrink type before a target shrinks.

## Adding a file to `web/`

A new file just needs an allowed extension: html, css, js or mjs, json, png, svg, woff2, txt or gz (served as is, for the page to unpack). Both apps serve any file under `web/` by its extension, and CI zips the whole folder. The Android app serves `web/` from its assets at `https://appassets.androidplatform.net/` (the interceptor in `MainActivity.kt`), and the iOS app serves it from the bundle at `lifepod://app/` (`WebFolderSchemeHandler` in `LifePodApp.swift`). Both give the page a real origin, so `'self'` in the CSP matches and module scripts load. Any other type, a path with `..` or a hidden file gets a 404.

For a new type, add it to `MIME_TYPES` in `MainActivity.kt` and `mimeTypes` in `LifePodApp.swift`. `tests/native.test.mjs` checks that the two tables match and that every file the page loads has a listed extension. Scripts must stay `text/javascript`, because both WebViews refuse a module script without a JavaScript type.

## Modules

The page is native ES modules, with no bundler or build step. `index.html` loads `dice.js`, a classic script that sets `window.lifePodDice`, then `app.js`, its one module script, which imports the rest from `web/js/`. Module scripts run once the document is parsed, in import order. Browsers don't run them from `file://`, so the tests, the design scripts and `npm run preview` serve `web/` over http (`scripts/serve.mjs`, the one static server), and the apps serve it from their own origins. Imports run one way, from the first folder here to the last:

- `logic/`: `data.js` (the fixed tables, limits and timings, and the small types they define), `save.js` (the save format, `loadGame` and the `fit*` checks), `rules.js` (the game's rules as functions of a game: who is out, play order, the designations' handoffs, applying an edit), `history.js` (the undo history's per-field deltas: diffing and applying them, merging a burst, the cap, their words and `fitHistory`) `cards.js` (card lookup's data format, folding, search and ranking, reading mana symbols, and finding a card's rulings in its shard; `scripts/cards-update.mjs` imports it too), and card lookup's query language (design/polish/SCRYFALL-SYNTAX-SPEC.md): `cardquery.js` (the parser), `cardterms.js` (colours, formats, costs, patterns, land nicknames), `cardcolumns.js` (the columns a query reads, built ahead of need), `cardkinds.js` (the `is:` values), `cardfilter.js` (evaluating and sorting a query) and `cardtypos.js` (close spellings). No DOM and no state.
- `ui/`: `dom.js` (the board's fixed elements, `element()`, the icons, and `syncChildren`, which keeps a row's keyed children in place) and `press.js` (`bindTap`, `bindCounter`, `bindSeat`, `bindStep`, `bindRelease`). DOM, but no app state.
- `state/`: `platform.js` (every call to a native bridge, or the browser's stand-in, and the screen), `state.js` (the game, `saveGame`, and what isn't saved: the board mode and where its edits began in the history, turn steps, reminders, strips being tapped) and `history.js` (the undo history while the page runs: the baseline, the open bursts, `record()`, stepping back and forward, and the toasts).
- `layout/`: measuring and fitting: `board.js` (the seats, the pill's place, the one tile size), `fit.js` (badge rows, mana strips and the life totals around them) and `settings.js` (the settings page's columns and fields).
- `render/`: drawing what the state says: `tile.js`, `badges.js`, `modes.js`, `pill.js`, `announce.js`, `appearance.js`, `history.js` (the running delta on a total) and `card.js` (a card, its result row, mana symbols and rulings, for card lookup).
- `actions/`: what a press changes, saves and redraws: `commit.js` (`commit()`, which records the change as an undo step, saves and redraws in one call; `step: false` for what isn't a game step), `dialog.js` (`showDialog`, which every dialog opens through), `board.js` (the tiles, life, a new game), `edits.js`, `history.js` (Undo, Redo and jumping through the history), `mana.js`, `mode.js` (board modes and "Who goes first?"), `turns.js` and `reminders.js`.
- `sheets/`: the settings page (`settings.js`, `options.js`, `slider.js`), the dice sheet, the History sheet (`history.js`) and card lookup (`cards.js`, with its search in `cardsearch.js` and loading rulings in `cardrulings.js`), which wire their controls as they load.
- `app.js`: wires the pill's other buttons, back and Escape, the window and the fonts, and boots.

A module imports only from its own folder or the ones before it, and nothing imports in a cycle. Where a renderer's button calls an action, as the turn chip and the mode cells do, app.js passes the actions in at boot (`setBadgeActions`, `setModeActions`) rather than the renderer importing upward. Only the module that declares a `let` assigns it; others read its live binding and call a setter such as `openBoardMode`, `setAskFirst` or `resetDrops`. Keep a module under 500 lines. ESLint enforces both rules (`eslint.config.mjs`): a `no-restricted-imports` block per folder names the folders after it, and `max-lines` caps every file in `web/js/`. The sheets add their listeners as they load, before app.js adds its own, so a dialog's close listener runs before "Who goes first?" looks; keep that order. A module's names aren't page globals: the native wrappers and tests call only what app.js sets on `window` (`closeOpenDialog`, `setReduceTransparency`, `setTextScale`). The design scripts import the modules they drive inside `page.evaluate` (`await import('/js/…')`, through `inPage()` in `design/polish/lib.mjs`), which returns the page's own module instances, and `tests/design.test.mjs` runs their page snippets, so a rename that breaks one fails `npm test`. Tests that read the page's internals, such as `layoutStats` or the live `game`, import them the same way, with `await import('/js/…')` inside `page.evaluate`; the page puts nothing on `window` for them.

## Styles

The CSS is eight plain stylesheets in `web/css/`, which `index.html` links in this order. The order is the cascade, as if they were one file, so a rule goes in the file for its concern, and a rule that must override others by coming later goes after them:

- `tokens.css`: the Mana `@font-face`, the design tokens and Classic's twelve tile palettes (`:root`), Material's token block, Glass's token block and Glass's fallbacks (no blur, reduced transparency, more contrast, short screens).
- `board.css`: the page base (box sizing, buttons, the focus ring), the Phosphor and Mana icons, the board and its rotation, and the centre pill with its round and mana buttons.
- `tile.css`: the Tile colours sets (`[data-tiles]`), each tile's palette (`data-colour`, `data-row`), the one size per board (`--u`, the badge size), the face, the background and the identity symbols, the total, Out, the life halves and seat rotation.
- `modes.css`: the mode layer and the board modes: tile colours, identity, commander damage, counters, mana and "Who goes first?".
- `badges.css`: the badge rows at rest and their chips, turns and rounds, the designations, reminders, the mana strip, the identity chip and the colour indicator.
- `settings.css`: the dialogs and their controls (buttons, rows, segmented choices with Tile colours' bands, switches), the settings page and the sliders.
- `cards.css`: card lookup: the search field, results, the card, the mana symbols in costs and rules text, and the compact layout for an open keyboard.
- `dice.css`: the dice sheet, then the page-wide blocks that must stay last: the hover states, reduced motion and the compact sheet spacing.

Use plain `<link>`s, not `@import`, which loads the files one after another, and keep the number of files small: the iOS app reads each one on the main thread. Every file starts with a comment that says what it holds. Don't add `@layer`, `@scope` or nesting: layers change which rule wins, and nested selectors can't be found with grep. Tools that read the CSS as text (the tests' `stylesCss`, `scripts/mana-codepoints.mjs`, the design scripts) list the files through `scripts/stylesheets.mjs`, which reads them from `index.html`, so adding a stylesheet needs only its `<link>`. `design/polish/tiles7.mjs` writes the `[data-tiles]` blocks in `tile.css` and the bands' `.tile-sets > [data-set]` lines in `settings.css`.

## Types

`npm run typecheck` runs TypeScript over every script in `web/` (app.js, the modules under `web/js/` and dice.js) through JSDoc comments, with no build step and nothing emitted (`tsconfig.json`, with `strict` and the `noUnused*` flags on). `tsconfig.logic.json` adds `noImplicitAny` for `web/js/logic/`, and `npm run typecheck` runs both; keep it at 0 errors. Each type sits next to the code it describes: the saved game is `@typedef Game` above `loadGame` in `js/logic/save.js`, the board modes (`BoardMode`) and the other small types the tables define, such as `CountKind` and `Tracker`, are in `js/logic/data.js`, and an editing mode's `Edit` is in `js/logic/rules.js`. A module uses another's type through a typedef import at its top, such as `/** @typedef {import('../logic/save.js').Game} Game */`. `types/globals.d.ts` declares the Android and iOS bridges, the dice API and what the page sets on `window`; change it with the native code. It's outside `web/` because the native builds package every file there. A new `game` field goes in the typedef as well as `loadGame`, and in `historyFields` or `settingsFields` (`logic/data.js`). Prefer a JSDoc cast, such as `/** @type {HTMLInputElement} */ (…)`, over changing code to satisfy the checker.

## Card data

Card lookup's data, every paper card's rules text from Scryfall, is `data/cards.json`, one card per line for readable diffs, and `web/data/cards.json.gz`, the same file gzipped, which the apps ship. `npm run cards:update` writes both (and the date in the credits); don't edit them by hand. It writes the rulings the same way: `data/rulings/` as text and `web/data/rulings/` gzipped, a shared file and 32 shards by a hash of each card's Oracle id (`scripts/cards-rulings.mjs`); `cards.json`'s `ru` gives each card's count and shard, and opening a card fetches only its shard. The page fetches the gzipped file only when card lookup first opens, through the CSP's `connect-src 'self'`, and unpacks it with `DecompressionStream`; nothing at startup may load it. A version tag refreshes the data for its release in CI (`scripts/cards-release.mjs`), falling back to the committed files; everything else builds from the committed files. `tests/cards-data.test.mjs` and `tests/cards-rulings.test.mjs` check their shape.

## The Mana font

`web/fonts/mana.woff2` is a subset with only the symbols the page draws. After adding or removing a Mana code point in a stylesheet or a script, run `npm run font:subset`, which rebuilds it from the original in `design/fonts/`. `tests/font.test.mjs` fails until you do.

## Tests

- Tests use `node:test` with Playwright through the shared harness in `tests/helpers.mjs`. Import `test` from there, not from `node:test`, and start every name with `node:` (no browser), `chromium:` or `webkit:`; a name without one fails its file. CI picks tests with `LIFEPOD_TESTS` (`node,chromium` in the web job, `webkit` in the iOS job); locally, `LIFEPOD_TESTS=webkit npm test` runs one engine.
- Open pages with `openPage(t, engine, options)`: one browser per file, a fresh context per page, the app over http from the local server in `scripts/serve.mjs` (`npm test` starts one for the run through the `globalSetup` in `tests/server.mjs`), and any page error or CSP violation fails the test. Use `reload(page)` and `seedGame(page, game)` rather than `page.reload()`, and the shared `tileProblems` for "a whole 44px target, inside its tile, clear of the pill".
- Time is fake: pass `clock: true` and move it with `page.clock.runFor(ms)` (or `hold(page, target, ms)`), and assert exact counts. Don't use `waitForTimeout`; wait for animations with `animationsDone` or for a result with `eventually`. Compare colours with `token(page, '--name')`, not values copied from the CSS. A test that checks a rule's text reads `stylesCss`, every stylesheet joined in link order. `tests/harness.test.mjs` checks all of this.
- Chromium pages, which stand in for Android, measure their text in Roboto 2.138 from `tests/fonts/`, so text-measuring tests (badge fitting, auto-drop) give the same result on a Mac, on Linux and in CI. WebKit pages, which stand in for iOS, keep San Francisco, the system font, as on an iPhone; WebKit runs on macOS locally and in CI. openPage's `font` option overrides either.
- The rules in `web/js/logic/` have no DOM, so `tests/logic.test.mjs` tests them in plain Node (`node:` tests): property tests with fast-check for `loadGame`, turn order, the monarch's and the initiative's handoffs and edits. `PBT_RUNS` sets the number of cases (500 by default). A new `game` field goes in its `Game` validator and generator there too.
- If you add or rename a `@JavascriptInterface` method, update `androidMethods` in `tests/helpers.mjs`. R8 shrinks the Android code, and `android/check-bridge.sh` (run by `build.sh` and CI) fails if a bridge method is missing from the built dex.
